## 项目：llm-session-proxy（工作区 D:\code\opensource\tpp 即项目根）

从零新建一个可发布到 npm 的 Node.js 工具，用途是给不支持会话头的 LLM 客户端做本地反向代理。
起因是 OpenCode Go / Zen API 要求 `x-opencode-session` 否则返回 400，而 Trae 等客户端无法自定义请求头。
参考实现：https://github.com/LIMTCYT/opencode-go-proxy-for-trae（纯 Python 标准库单文件）。

### 关键决策

- **包名 `llm-session-proxy`**（用户从 3 个候选里选定；`llm-proxy-inject` / `opencode-proxy-kit` 备选，registry 上均未被占用）。
  刻意不绑定 opencode/trae，突出「通用 + 自定义参数」。
- **零依赖 ESM，Node >= 18**，纯内置模块（http/https/crypto）。理由：`npx` 启动无安装负担。
- **能力是参考实现的超集**：会话 ID 三级策略、模板化头注入、模型别名（前缀剥离 + map）、路径重写、
  请求体参数注入/删除、本地状态端点。参考实现只做 Trae 那一件事，本工具把这些全部配置化。
- **配置四层合并**：默认值 < 配置文件 < 环境变量 < 命令行。配置文件是宽松 JSON（支持 `//`、`/* */`、尾随逗号）。
- **默认值对齐 OpenCode Go**（上游 opencode.ai、端口 9355、注入 4 个 x-opencode-* 头、剥离 `proxy-` 前缀），
  这样 `npx llm-session-proxy` 开箱即用；换上游只需改配置。

### 验证结果

- `node --test`：24 个测试全绿（会话引擎 + 端到端代理，含 SSE 分块时序、4xx 错误体透传、502 兜底）。
- CLI 冒烟：真实 spawn 进程 + 假上游，确认会话 ID 稳定、请求号递增、模型别名剥离、UA 替换、auth 透传。
- `npm pack --dry-run` / `npm publish --dry-run`：13 个文件、28.5 kB，prepack 自检通过。

### 遗留 / 阻塞

- **GitHub 推送到 alaahong 尚未完成**。沙箱内 GitHub HTTPS 通道不通：
  `gh auth login --web` 两次都返回 `Post "https://github.com/login/device/code": Bad Gateway`；
  `curl` 直连 api.github.com 超时、走代理 000。但 **SSH 通道完全正常**（`ssh -T git@github.com` 认到 alaahong，
  `git ls-remote` 能返回明确的 "Repository not found"）。结论：需要用户手动创建空仓库，之后用 SSH 推送。
- 远端已配好：`origin = git@github.com:alaahong/llm-session-proxy.git`，本地 main 已有首个提交（26e2871）。
- npm 发布只做到「可发布」。注意本机 npm registry 指向 `registry.npmmirror.com`，
  真要发公网需加 `--registry https://registry.npmjs.org`。

### 踩坑

- **同一文件的多个 Edit 并行发出会互相覆盖**：4 个 Edit 同时改 src/proxy.js，只有最后一个生效，
  前三个静默丢失，导致语法错误。修法：对同一文件必须串行 Edit，或改用 Write 整体重写。
